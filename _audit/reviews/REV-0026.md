## 2. 发现（R1–R8）

### R1（S3）：冻结 min_n=64 / stat plan n_per_arm=64 与实际可评窗 59 不一致，且判定器未机械消费 min_n
- **证据**：`config/evidence/min_effects.yaml` 行 190 `p1_physical_signal_carriage … min_n: 64`；`config/evidence/stat_plans/p1_physio.yaml` 行 93 `n_per_arm: 64`、行 25 `capture_cycles: 65（64 个连续差分窗 + 1 cycle 原点）`。实测可评窗 **59**（首差分 busy[0]=None 结构性缺席 1 + 对齐窗尾部未到期 4——语义成文但账目未回写）；`evaluate_p1_signal_carriage` 的 `inputs_ok = n_windows >= 3`，**全库无任何代码消费 min_n**（grep 实证）→ 冻结阈值 64 在 P1 名义上未满足却未触发任何拒判。
- **影响**：判决方向不受影响（r=1.0 饱和、p=0，任意合理 n 下均 SUPPORTED），非判据降低；但属"冻结阈值与实现/账目不一致 + 无机械断言"缺口——REV-0014 R9 先例（ECE 每箱≥30 须机械断言）确立过同类义务。
- **建议**：ADR-G-0026 补裁钉死口径——n_per_arm/min_n 语义勘误为"capture 名义差分窗 64；可评窗 = 59（首差分 1 + 对齐窗尾部 4 结构性缺席，成文语义）"，或将 min_n 断言以结构口径（59 = 65 − 1 − W_align）纳入判定器。

### R2（S4）：composite 判定调用 `recompute_ok=True` 硬编码——永真门
- **证据**：`runs_p1.py` 行 433 `recompute_ok=True` 字面传入 `evaluate_p1_composite`；该参数是 composite SUPPORTED 的必要条件（`hypotheses.py` 行 761–765），但 P1 runner 中不存在将其置 False 的任何计算路径。
- **影响**：无遮蔽——复算语义已由 `i1_match = fidelity.recompute_ok`（replay_bit_exact ∧ derive_recompute_ok，真实计算）承载；但空转参数违反 INC-08"探针必须能失败"精神。
- **建议**：绑定 `fidelity.recompute_ok` 或删参。

### R3（S4）：Fisher z CI 在 r=1 饱和处退化为 [1.0, 1.0]
- **证据**：`runs_p1.py` `_fisher_z_ci`：abs(r)≥1 → z=inf → tanh(inf±…)=(1.0,1.0)；首评工件 `"ci": [1.0, 1.0]`。r=1 的 95% CI 统计上不应为点区间，上界 1.0 无区间语义。
- **影响**：判定仅消费下界（>0），方向不受影响；stat plan `effect_ci_rule: fisher_z_95ci` 未定义饱和退化情形。
- **建议**：成文退化情形（r=±1 时 CI 记 saturating 并注记），或在计划内改用精确二项/置换下界。

### R4（S4）：`estop_latency_within_bound` 场景断言弱（纯算术单值）
- **证据**：`runs_p1.py` 行 232–235：`estop_latency_cycles(64, 65) <= 1`，而被测函数本体即 `max(0, estop−cmd)`——恒真式断言；真实上界语义（急停后首个校验点拒绝）实际由 estop_floor 场景的 `submit(...) == REJECTED_ESTOP` 承载。
