# Tessera 创始 Prompt · v1.0 · 2026-09-18

> **用法**：在空目录启动 ZCode，将本文件全文作为第一条指令发出；你的第一个任务见 §9。
> **名称**：Tessera 为工作名（拉丁语"马赛克镶嵌片"：单个立方体 = 一块自足的镶嵌片，四面扩展口并联 = 拼合成任意规模的 I/O 系统）。owner 一句话可全局替换，替换时同步 §0 与全部出现处。
> **前因（为什么有这份文件）**：本项目自一个更大的 AI 项目（Galatea）的固件子项目剥离而来——剥离动因：过于庞大的单一项目不利于 AI 开发。历史教训（阶段越权产出被全量撤回、编码事故损毁文档、选型无裁决导致返工、标识符撞名、文档不自包含导致 owner 无法裁决）已全部转化为本文件的规则。**与 Galatea 无任何开发耦合**，未来是否接入另议。

## 0. 使命

建造**立方体智能 I/O 模块（Tessera）**：基于 Zephyr RTOS 的模块化末端输入输出系统——业务逻辑以**可安装、可迁移的 APP** 形态运行（类安卓：APP 与具体板卡硬件解耦）；输入输出外设**可插拔**；多个立方体可经扩展面**并联为一个逻辑节点**以支撑更复杂的外设；物理输出具备**安全限制**；配套一个 **AI Agent（MCP 形态）**，能完成"需求分析 → 软件设计 → 编程开发 → 模拟测试 → 部署"的完整链路，对模块进行编程。

选择 Zephyr 的原因（owner 裁定）：兼容多种芯片生态 + 获得类 Linux 的驱动管理能力（Devicetree/统一的设备驱动模型）。

本项目**完全由 AI（ZCode）开发**，owner 负责裁决与 review。

## 2. 开发流程：阶段门 + 人工 review

### 2.1 主线

```text
research → owner 裁决 → design（规格）→ owner 确认 → impl（实现+测试）→ 阶段退出 review → 下一阶段
```

### 2.2 阶段产出白名单（越权产出 = 立即撤回并留痕）

| 阶段 | 允许产出 | 禁止产出 |
|---|---|---|
| research | `docs/research/*.md`、Q 登记 | 一切实现物（源码、构建文件、可运行配置） |
| design | `design/` 规格文档 + 修订记录 | 代码 |
| impl | 规格清单内代码 + **同批测试** | 清单外文件；无出处的魔法数值 |

### 2.3 单会话预算

一个会话交付**一个可验证交付单元**（一份文档、一个 Q 批次、一个模块及其测试）。超出部分登记待办另起会话。（前因：旧项目曾单会话越权产出 27 个实现文件。）

### 2.4 人工 review 门（必须停下等 owner，不得自裁）

触发点：① 一切选型与默认值（先登记 Q）；② 阶段退出（对照 DoD）；③ 公共 API / 文件格式 / 网络协议 / 权限模型变更；④ 安全合同（§5）任何改动；⑤ 技术栈变更（须证明**阻塞性**，"更好"不构成理由；附备选对比与迁移成本）。

**呈递格式（强制，不自包含直接重写）**：每项须含——**背景**（现状是什么、为什么现在是问题）→ 选项 → 建议 → 影响。owner 可批量回复"全部按建议 + 例外"。

### 2.5 决策登记册 `decisions.md`

- 生命周期：`Q-xx`（待裁）→ owner 回复 → `DEC-xx`（已裁，附日期与原文）；编号不复用，REJECTED 留档。
- **默认值三问**（写任何常量前自答）：从哪来（Q/推导）？越界会怎样？改动破坏什么？

## 3. 工程纪律（军规十条，违反即流程缺陷）

1. **流程至上**：阶段白名单不越、review 门不闯。
2. **无 Q 不落盘**：未裁决的默认值/选型不得写成"已决定"，不得进代码常量。
3. **文字纪律**：只记录必要内容（删掉会造成信息损失/决策不可溯才是必要）；必要内容必须**自包含**——现状 + 动因 + 后果三要素齐全，不带会话上下文也能读懂。（前因：owner 曾因呈递不自包含而无法裁决。）
4. **编码纪律**：全库文本 UTF-8 无 BOM；批量文本操作显式指定编码；禁用依赖系统代码页的工具（前因：旧项目曾因此不可逆损毁 8 份文档）。
5. **git 纪律**：仓库第一时间 git 化；每交付单元一提交 + 会话结束兜底提交；里程碑与重大裁决打 tag；失败与回退留痕，禁改写历史。
6. **命名纪律**：跨文档标识符（DEC/Q/M/REQ/模块名/板名）登记于 `docs/names.md`；新造先查碰撞；禁裸单字母作跨文档标识符（前因：旧项目 D/L/M/S/N 五组撞名，290 处返工）。
7. **测试同批**：实现与测试同一交付；失败如实报告，禁美化、禁把失败改写为"选择不行动"。
8. **结论落盘**：聊天与记忆不是项目状态；会话结束前把持久结论写入文档/登记册。
9. **顺手重构禁止**：任务外的发现登记不动手，不混入本批交付。
10. **交付即验证**：DoD 对照 + 构建/测试全绿 + lint 通过，才算完成；有缺口如实列出。

## 5. 安全与确定性合同（继承自旧项目调研；HLD 可细化，不得削弱）

1. **三安全态**：每个输出通道（含受控供电）显式声明上电态 / 断链态 / 故障态；无声明不予注册。
2. **写入路径唯一**：一切输出必经保护层校验（限幅 / slew-rate / 限流）后才落驱动；绕过保护层的写入 = 缺陷（须可机械检查）。
3. **断链 fail-safe**：宿主/网络失联 → 输出进安全态；输入流不因保护而中断。
4. **看门狗**：超时 → 全输出安全态；每子系统独立喂狗（可定位卡死来源）。
5. **estop 硬件通道**：急停 ISR 直达安全态，**不经协议栈、不经调度排队**；响应时间上界可测；事后补发事件。
6. **初始化顺序固定**：任一步失败 → 全系统 fail-safe，不得半启动。
7. **受控供电**（DEC-03）纳入 1–6 同一合同（它是特殊形式的输出）。
8. **并联安全归属**（对应 DEC-02 遗留题）：estop 与保护必须能在**本地立方体**独立生效，不依赖逻辑节点内部通信——这是逻辑节点拓扑设计（主从/协商）的硬约束。
9. **确定性**：同一输入序列必得同一输出序列（调理链与控制逻辑，重放测试机械验证）；禁依赖未播种随机、墙钟、容器迭代序。
10. **固件核心不学习**：安全参数、权限模型、输出限值不经运行时自适应修改；APP 权限清单是硬边界，越权访问一律拒绝并留痕。

## 6. APP 与 AI Agent（HLD 的核心输入）

- **APP**：可打包、可跨板迁移（依赖框架 HAL 而非具体硬件）；声明式权限；签名分发；版本化与失败回滚（DEC-04/05）。重实时/硬确定任务实现在框架层（原生代码），APP 承担业务编排——沙箱性能预算由此划分。
- **Tessera Agent**（DEC-11/12）：MCP server；能力链 = 需求分析 → 软件设计 → 编程开发 → 模拟测试（DEC-13：native_sim + 外设桩）→ 部署；产出 = 业务 APP **与** 硬件配置。**Agent 无豁免权**：其生成的一切产物走与人类产物相同的签名、权限、安全合同检查链。
- Agent 自身的开发同样走 §2 流程；其特有 review 点：MCP 工具面变更、模拟器保真度声明的修订。
